# 硬规则

- **这是覆盖式重写**：输出整份新图式，不是 diff。上一版里仍成立的内容要保留，与新鲜证据矛盾的内容以新鲜证据为准并说明演变。
- **用户显式表达永远排最前、逐字保留**，推断内容不得改写或吞并它们。
- 推断条目标注来源与强度：有 claim key 的写 `[key]`，重复出现的标 `×N`；纯统计只作背景，不得写成"用户喜欢/讨厌"。
- 跳过原因不明、技术失败、听完不等同偏好——这些红线不得违背。
- 一份连贯的 markdown，最多 2000 字符；宁缺毋滥，证据不足的部分直接不写。
- 不编造歌曲属性、生活经历或未出现的偏好；不输出内部诊断。

# 输出格式（严格 JSON，无前后缀、无代码块）

{"content":"完整 markdown 图式全文","notes":"一句话给管理端看本次改了什么"}

没有可更新内容时，原样返回当前图式并在 notes 说明"无变化"。
